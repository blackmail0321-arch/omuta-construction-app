# 四月はじまり — 予定と休暇

工事管理アプリとは別の、個人用の予定・休暇アプリです。4月始まり、予定と実施の比較、休暇の取得・残日数と時間休の残時間を扱います。

**初期の予定・メモ・個人情報は含まれていません。** Excelまたは旧アプリのJSONバックアップを利用者の端末で取り込んでください。取り込み内容はGitHubへ送信しません。祝日は元データを同梱せず、日本の祝日ルールで計算します。将来の春分・秋分や法改正などによって変わる場合があります。

## 休暇の表示と繰越・失効見込み

[公開アプリを開く](https://blackmail0321-arch.github.io/omuta-construction-app/)。有給・子の看護・時間休などのラベル枠だけを赤く表示し、日付全体の背景と数字は変えません。有給と子の看護休暇の残りは「○日○時間」で表示します。時間休を残日数から差し引くかは従来の設定に従います。

「休暇の利用状況」→「有給の繰越・失効見込みを確認」を開くと、翌年3月31日の失効見込みと、今年の繰越分の消化状況を確認できます。初期は折りたたみ、カレンダー上部には表示しません。

「付与・繰越日数と時間休を設定」で、次の3項目を分けて入力します。

- 有給の付与・繰越合計：今年利用できる合計。繰越分を二重加算しません。
- 翌年度に繰り越せる有給の上限：例8日。**年度末の残り見込み12日－上限8日なら、4日分が消滅する見込み**です。
- 今年の繰越分：以前に設定した今年の繰越分は、そのまま消化状況の表示に使用します。翌年度の上限へ自動で流用しません。

年度末の残り見込みには期限内の登録済みの未来の取得予定を含め、今日までの入力による残りと分けて表示します。上限未設定時には失効日数を推測しません。繰越分から先に使う消化状況も、予定と今日までの入力を区別します。実際の取得は入力内容と照合してください。予定・メモ・既存の付与合計を保持し、新しい上限設定もJSONバックアップへ保存します。

画面上部の「更新を確認」は常に表示します。最新版ならその旨を表示し、新しい版があれば確認後に「アプリを更新」へ進みます。オフライン・通信エラー時もボタンを残します。入力画面を保存して閉じてから更新してください。旧版に新しいボタンが見えない場合は、Safariで公開URLを読み込み直してから更新します。

## ダウンロード

[アプリ一式（planner.zip）をダウンロード](https://github.com/blackmail0321-arch/omuta-construction-app/raw/refs/heads/main/apps/april-planner/planner.zip)

非公開リポジトリの場合、アクセス権のあるGitHubアカウントでログインしてください。直接リンクで取得できない場合は、[ZIPのファイル画面](https://github.com/blackmail0321-arch/omuta-construction-app/blob/main/apps/april-planner/planner.zip)で「Download raw file」（下向き矢印）を選びます。

## PCで最初に使う

1. 上のZIPをPCに保存します。
2. ダウンロードしたZIPを右クリックして「すべて展開」。展開した `planner` フォルダをドキュメントなどへ保管します。
3. PCだけで使う場合は `index.html` をChromeやEdgeで開きます。ブラウザによってファイルの直接表示や保存を制限する場合は、次の配信方法を使ってください。
4. 同じファイル・同じブラウザで継続して使い、定期的に「バックアップ」でJSONを保存します。

旧版で追加した記録は、旧版の「バックアップ」でJSONを保存し、新版の「Excel・バックアップの取り込み」から読み込みます。元の2行構成の `.xlsx` も取り込めます。

## iPad mini単独で使う（ホーム画面・オフライン）

この版は、ホーム画面へ追加してPCなしで使う仕組みに対応しています。**初回の保存と更新だけ、インターネットにつながるHTTPS公開先が必要です。公開先は上記の公開アプリです。GitHubのファイル画面やrawのHTMLは起動用URLとして使えません。**

1. iPadのSafariで、設定したHTTPSの起動用URLを開きます。
2. 「オフライン利用の準備完了」の表示を待ちます。未完了ならネットワークを確認し「準備を再試行」を押します。
3. Safariの共有ボタン→「ホーム画面に追加」。表示される場合は「Webアプリとして開く」をオンにします。
4. ホーム画面のアイコンから、通信できる状態で一度起動し、準備完了を確認します。
5. ホーム画面側のアプリでExcel・JSONバックアップを取り込みます。PCやSafariタブのデータは自動では移りません。元の画面でバックアップしてから取り込んでください。
6. Wi-Fiとモバイル通信を切り、いったんアプリを閉じ、ホーム画面から再び開けることを確認します。その後はPCを起動せず、オフラインで予定・実施の入力、検索、休暇集計、バックアップ・取り込みを使えます。

利用データはiPad内に保存し、サーバーへ送信しません。アプリやSafariのデータ削除、空き容量不足などで失われる可能性があるため、定期的にJSONバックアップを「ファイル」に保存してください。アプリ更新は通信中に行い、入力を保存して画面を閉じてから「アプリを更新」を押します。更新は記録を保持します。

### GitHub Pagesで初回の配信先を用意する

このリポジトリでは、予定表・電験アプリの対象ファイルをmainへpushしたとき、または手動実行時に、既存のGitHub Pagesを更新します。公開済みの各アプリを組み合わせて配信し、元Excel・個人の予定データ・工事アプリのソース一式は公開用成果物に含めません。

1. GitHubのリポジトリで Settings → Pages → Build and deployment → Source を「GitHub Actions」にします。
2. Actions →「Publish April planner (manual)」→「Run workflow」を選び、mainブランチで実行します。
3. 完了後、実行結果の `github-pages` に表示されるURLが、iPadのSafariで開く起動用URLです。
4. その後は上記の「ホーム画面に追加」の手順へ進みます。

この設定・手動実行によってアプリ本体を公開します。既存のGitHub Pagesがある場合は、その配信内容を置き換える可能性があるため、先に運用先を確認してください。リポジトリ管理者による操作が必要です。ワークフローと配信用ZIPの作成は、公開設定の有効化やデプロイ成功を意味しません。

### 配信担当者向け

`offline-site.zip` を展開し、その中身をHTTPSの静的サイトとして配信します。アプリ以外のサイト全体に影響しないよう、専用のディレクトリ・URLを継続利用してください。`index.html`、`service-worker.js`、`manifest.webmanifest` と `icons/` を同じ階層へ置きます。JavaScriptとmanifestのContent-Typeを適切に設定し、`service-worker.js` に長期の固定キャッシュを指定しないでください。GitHub Pagesなど新しい公開先の作成や設定変更は、このZIPを作るだけでは行われません。

アプリ本体とアイコンだけをキャッシュし、元ExcelやJSON・予定データ・他のアプリのURLはキャッシュしません。初回の一括保存に失敗した場合は旧版を維持し、更新は利用者の操作後に反映します。

## PCからiPad miniへ配信する従来の方法

インターネット回線は不要ですが、この方法ではPCを起動し、PCとiPadを同じWi-Fiにつなぐ必要があります。

1. PCへ [Python 3](https://www.python.org/downloads/) を導入します。
2. Windowsは `start_windows.bat` をダブルクリック。Mac/Linuxはターミナルで展開フォルダへ移動し `bash start_mac_linux.sh` を実行します。
3. 起動した画面を開いたままにします。PCのブラウザでは `http://localhost:8026` を開きます。
4. Windowsではコマンドプロンプトで `ipconfig` を実行し、接続中のWi-FiのIPv4アドレスを確認します。Macではシステム設定→Wi-Fi→接続先の詳細→TCP/IPで確認します。
5. iPadのSafariで `http://PCのIPv4アドレス:8026` を開きます。例：PCのIPが `192.168.1.20` なら `http://192.168.1.20:8026`。このIPは例なので実際の値に置き換えます。
6. PCがスリープしたり配信画面を閉じると、iPadから接続できません。配信を終了するときは Ctrl+C。

配信にはログイン保護がありません。信頼できるプライベートネットワーク内で使用してください。ファイアウォールの確認ではそのネットワークだけ許可します。

**PCとiPadの入力データは自動同期しません。** ブラウザの端末内保存です。変更を別端末へ移す際は、JSONバックアップを転送して取り込みます。PCを経由せずに使うには、上記のHTTPS配信とホーム画面への保存を行います。

## 予定・実施と休暇

- 上段は予定、下段は実施。それぞれ内容・メモを入力します。カレンダーは上下、一覧は左右で比較します。
- 旧Excelや旧版の下段は実施済みとは扱わず、未分類の旧下段として保持します。内容を確認して予定・実施へコピーできます。
- 「休暇の利用状況」は独立したカテゴリーです。取得・残日数、時間休の使用日数と時間、残時間、月別集計を確認できます。
- 「付与日数・時間休の上限を設定」で年度別の付与＋繰越合計や上限時間を入力します。未設定と0は区別します。
- 時間休を有給・子の看護休暇からも差し引くかは設定で選択します。集計には登録済みの未来の予定も含みます。
- バックアップは形式2。旧形式1も読み込めます。形式2は旧版アプリで編集しないでください。

## 開発と検証

分割ソースを編集し `python3 build.py` でHTML、キャッシュ更新用のバージョン付きservice worker、配布ZIPとHTTPS配信用ZIPを再生成します。生成HTMLのみを直接編集しないでください。

- `node tests/core.cjs`：年度、うるう年、祝日、休暇・上限計算。
- `node tests/distribution.cjs`：PlaywrightとChromiumが必要。テスト用のローカル配信を自動起動します。
- `node tests/offline.cjs`：通信を切った状態での再起動・編集・保存・JSON移動、更新の失敗時保護、入力中の更新防止、更新後の記録保持を検証します。
- `OMUTA_PLANNER_URL` と `CHROMIUM_PATH` でテスト先・ブラウザ実行パスを変更できます。
- 初期予定データが空であること、入力・保存・再読込、予定／実施比較、年度設定、旧形式の取り込み、バックアップを検証します。

実機iPad/SafariやWindows上の起動スクリプト実行は未検証です。単体HTMLは外部のスクリプト・フォント・画像の取得を必要としません。

fflate 0.8.2を使用しています。ライセンスは `vendor/LICENSE-fflate`。
