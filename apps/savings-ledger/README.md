# つみかさね — 給与と財形の記録

貯蓄計算Excelの入力項目を引き継ぐ個人用アプリです。公開用のソースや配布ZIPに給与・個人の記録は含みません。元Excel、PDF、JSONは利用者の端末内で読み取り、サーバーへ送信しません。

- 元Excelの「Sheet1」「明細取込一覧」「給与明細比較」を読み込み、給与・賞与・差額支給、貯蓄表の予定、月単位の引き出し履歴を取り込みます。
- 支給前の積立予定を確定残高へ含めません。元Excelの残高セルや年度間の集計式は使わず、開始残高＋確定明細の財形積立＋入金調整−引き出しで再計算します。
- 開始残高が分からない場合は「累計差額」として表示します。利息などは入金調整として記録できます。元Excelで引き出し日が記載されていない場合、日付を推測せず年月だけで保存します。
- PDFの文字抽出、画像PDFの日本語OCR、確認・修正後の保存に対応します。同じ年月・区分は更新し、二重加算を防ぎます。読めなかった金額は空欄、積立なしは利用者が0円を確認して登録します。
- 総支給−控除＝手取り、口座内訳の振込合計＝手取りを照合します。残高や明細の入力は業務・銀行の確定記録と照合してください。
- 元PDFの全体やExcelファイル自体は保存せず、確認した金額・内訳・元ファイル名などを保存します。

## パスフレーズとセキュリティ

初回に16文字以上・6種類以上の文字のパスフレーズを設定します。端末内の記録・取り込み前の復元用コピー・JSONバックアップを暗号化します。解除後だけ記録を表示し、無操作5分または画面を離れて30秒以上でロックします。未保存の入力は破棄されます。**パスフレーズを忘れると復号できません。** 安全な場所に保管してください。詳細と限界は [SECURITY.md](SECURITY.md) を参照してください。

## 最初の操作

1. 公開後のアプリをSafari/Chromeで開き、パスフレーズを設定・解除してから、「Excel・バックアップを取り込む」から元Excelを選びます。
2. 取り込み件数・引き出し履歴・財形の累計差額を確認し、開始残高が分かれば設定します。
3. 次の給与・賞与が出たら「明細PDFを読み込む」でPDFを選びます。複数ページの場合は対象ページを選択します。
4. 文字のないPDFなら「画像から読み取る（OCR）」を押します。元ページと金額・対象月・区分・財形額を確認して保存します。OCRは時間がかかり、画質・書式によって誤読します。
5. 財形を引き出したら「財形の入出金」で年月・金額・メモを登録します。残高を再計算します。

給与明細PDFの実例はまだ受領していないため、特定の勤務先の書式での読取精度は未検証です。実際のPDFを用いた確認・調整が必要です。読み取り候補を無条件に自動登録する設計ではありません。

## iPad・スマホとオフライン

HTTPSの公開URLをSafariで開き、読取機能を含めた「オフライン利用の準備完了」を待ち、「共有」→「ホーム画面に追加」。アイコンから一度オンラインで開き、準備完了後に通信を切って再起動します。初回は日本語OCR・PDFのファイルを保存するため通信量・時間がかかります。

入力した記録は端末ごとに保存します。PC/iPad/スマホの自動同期はありません。暗号化JSONバックアップをファイル等で移し、別端末のアプリで取り込みます。バックアップ作成時のパスフレーズで解除してから、その端末のパスフレーズで暗号化して保存します。取り込み前のバックアップと直前の復元機能があります。ブラウザデータ・アプリの削除や容量不足に備え、定期的にバックアップしてください。

## 開発

`python3 build.py` でHTML、service worker、HTTPS配信用 `offline-site.zip` と `savings.zip` を生成します。分割ソースを編集し、元の私的Excel・給与PDFや実際の金額をリポジトリや公開物へ含めないでください。

単体HTMLのファイル直接表示ではPDFモジュールの読み込みがブラウザに制限されるため、PDF/OCRはHTTPSまたはローカルHTTP配信から利用します。ライブラリはすべて同梱し、実行時の外部CDN・AI API・認証キーは不要です。

依存ライブラリのバージョンは `vendor/VERSIONS.json`。npm取得時にSHA-512のSRIを検証済み。OCR言語データは `tesseract-ocr/tessdata_fast` の固定コミットに基づき、`vendor/ocr/lang/SOURCE.json` に取得元とSHA-256を記録しています。ライセンスは各vendor配下に同梱しています。

## 公開とテスト

予定表と同じ手動公開ワークフローで、予定表は従来のURL、貯蓄アプリは `/savings/` へ配信します。公開処理が成功するまでは新しいURLから利用できません。公開用ZIPには給与や貯蓄の個人データを同梱しません。

- `node tests/core.cjs`：計算・読み取り候補のパーサー。
- `python3 tests/fixtures.py /tmp/savings-fixtures`：架空のExcel・文字PDF・画像PDFを生成（テスト用Pythonのopenpyxl/reportlab/Pillowと日本語フォントが必要）。
- `node tests/browser.cjs`：実際のPDF/OCR、引き出し、保存、比較、暗号化バックアップ。
- `node tests/security.cjs`：改ざん・誤パスフレーズ・CSP・XSS・競合・自動ロック。
- `node tests/offline.cjs`：通信を切った再起動と解除、OCR、キャッシュ改ざんの検出。

ブラウザテストはPlaywright/Chromiumを使い、テスト用配信を自動起動します。実際の給与データをテストコード・フィクスチャとしてコミットしないでください。
