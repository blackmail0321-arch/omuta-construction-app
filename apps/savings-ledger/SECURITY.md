# セキュリティ仕様と確認範囲

このアプリは、給与・貯蓄記録を利用者の端末内で処理する設計です。アプリ公開サイトに記録を送信するAPI、外部AIサービス、アクセス解析は実装していません。「絶対に侵入されない」「銀行と同等の認証済みシステム」といった保証はしません。

## 保存と解除

- 端末内の主データと取り込み前の復元用コピー、JSONバックアップをAES-256-GCMで暗号化します。毎回ランダムな96ビットIVを使い、保存用／復元用／バックアップ用の用途を追加認証データに含めます。
- 利用者が設定する16文字以上・6種類以上の文字のパスフレーズから、128ビットのランダムなソルトとPBKDF2-HMAC-SHA256（600,000回）で鍵を導出します。
- 鍵は非抽出のCryptoKeyとしてメモリだけに保持します。パスフレーズや復号鍵をlocalStorage、CacheStorage、URL、サーバーに保存しません。解除後、入力欄も消去します。
- 暗号化の認証に失敗したデータは取り込みません。破損した記録を黙って初期化・上書きしません。
- 既存の非暗号化データがある場合は、初回のパスフレーズ設定後に暗号化へ移行します。
- パスフレーズを忘れた場合、提供者が復号・リセットして元の記録を取り戻すことはできません。安全なパスワードマネージャー等で保管してください。バックアップの復元には作成時のパスフレーズが必要です。

## 画面と更新

- 手動ロック、5分無操作でのロック、画面を離れて30秒以上経過した後のロックを行います。画面を離れた際は表示を覆います。ロックではメモリを破棄して再読み込みするため、未保存の入力は失われます。OSによるスクリーンショット取得などを完全に防ぐ保証ではありません。
- 他の画面による保存変更を検出し、古い画面が新しい記録を上書きしないよう保存前・暗号化後に再確認します。
- アプリ更新は手動確認後に反映し、入力画面が開いた状態では更新しません。
- データ表示用のデバッグAPIは公開サイトでは作りません。自動テストのためlocalhost/127.0.0.1だけで有効にします。

## 不正な入力・外部通信への対策

- HTMLへ表示する入力値をエスケープします。値をスクリプトとして解釈しません。金額は整数・上限・合計の安全範囲を検証し、総支給−控除＝手取り、入力された口座の振込合計＝手取りを照合します。
- Content Security Policyで、埋め込みスクリプト・スタイルをビルド時のSHA-256に限定し、JavaScriptのunsafe-eval／unsafe-inlineを許可しません。WASMはOCR/PDFのため明示的に許可します。通信先は同一オリジンと端末内のblob/dataに限定します。オブジェクト埋め込み・子フレーム・フォーム送信を禁止し、他ページのフレーム内でのアプリ起動も停止します。
- PDFは最新取得時に固定したPDF.jsで、JavaScript評価・XFA・動的フォント面を無効にしてCanvasへ描画します。PDFのアクションやリンクは実行しません。サイズ・ページ数・画像画素数・描画範囲・読取時間を制限します。
- OCRはローカルの日本語・英語モデルで実行し、画像を外部サービスへ送信しません。読取候補は人の確認後に保存し、未読の金額を0円と判断しません。
- Excelの外部参照・マクロ・数式を実行せず、XMLの値を読みます。DOCTYPE/ENTITYを拒否し、ZIPの圧縮前後の容量・シート数を制限します。
- 元PDF・元Excelそのものはアプリ内へ保存しません。利用者が別途保存した原本・CSVはアプリの暗号化対象ではありません。CSV出力は平文であることを確認してから行います。

## 配布の信頼性

- npm配布物の取得時にSHA-512のSRIを照合しました。OCR言語データは固定コミットを取得し、SHA-256を記録しています。
- `vendor/SHA256SUMS.json` に依存ファイルの期待ハッシュを記録し、ビルド時に検証します。期待ハッシュを検証回避のために変更しないでください。
- オフライン保存時は各ファイルのSRIを検証し、キャッシュから返す場合もSHA-256を照合します。改ざん・不完全な更新では旧版を維持します。利用者の記録や元明細はキャッシュしません。
- GitHub Pagesの公開処理は手動実行・mainブランチだけに限定し、Actionsのバージョンを公式のコミットSHAに固定しています。checkoutの認証情報を残さず、ビルド・公開で権限を分けます。公開用成果物はアプリ本体だけで、個人データを含みません。

## 端末・アカウント側で必要な保護

OS・Safari/Chromeを最新にし、端末の画面ロックを利用してください。GitHubの公開元アカウントには二要素認証やパスキーを設定してください。これらは利用者のアカウント／端末の設定であり、このコードを配置するだけでは有効になりません。

ロック解除中の端末の乗っ取り、悪意あるブラウザ拡張・マルウェア、パスフレーズの流出、公開元アカウントそのものの侵害、OSの脆弱性などは、オフラインWebアプリだけで完全に防ぐことはできません。新しい脆弱性に対応するため、依存ライブラリとアプリを継続的に更新する必要があります。

## 検証

テスト用の架空データで、暗号化保存・バックアップ、誤パスフレーズと改ざん拒否、別端末キーへの取り込み、XSSと外部接続の制限、上書き競合、自動ロック、文字PDF・画像PDFのOCR、オフライン再起動・OCR・キャッシュ改ざんの拒否を検証します。実際の勤務先のPDF書式と実機iPad/Safariは、利用者の資料・端末での確認が必要です。
