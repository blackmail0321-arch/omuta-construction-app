# 端末内の図形数量拾い出し：検証用試作

2026年11月6日。利用者が図面記号からの数量候補を早期に希望。外部AIへ図面を送らない条件を維持する。

現在の本番アプリの数量処理はOCR/原文記載値の抽出であり、図形認識は含まない。この試作は本番へ接続していない。将来の機能追加・完成日・実図面での精度を保証するものではない。

## 今回作成した基礎処理

`matcher.cjs` は二値画像の記号例と同じ向き・サイズの形を探索し、候補位置と候補個数を返す。背景線の許容と重複位置抑制、画像・探索量の上限、不完全探索の明示を含む。類似度は正解率・確信度ではない。図形から機器名や工事区分を推測する処理ではない。

`node experiments/local-drawing-takeoff/test.cjs` は人工の単純な記号3個と異なる形、探索打切り、入力制限を確認する。実図面での検出率・誤検出率、iPad性能は未検証。回転/縮尺差、潰れ、線が重なる記号、複雑なスキャンは未対応。現在は同期の検証用関数であり、そのまま主画面へ組み込まない。

## 本番へ接続するための必要作業

1. 利用者が提供する実際の平面図1ページと凡例で、照明器具1種類の記号を指定して検証する。アプリ画面の画像・縮小された全画面キャプチャからは記号精度を評価しない。
2. 元画像・表示画像・記号例の座標系を固定する。元ファイル識別情報、ページ、対象範囲、記号例、処理条件を記録する。
3. Web Worker/小分け処理と進捗/取消を追加し、iPadでのメモリ・待ち時間を計測する。全範囲を処理できていなければ全体数量として表示しない。
4. 候補位置を図面上の枠で示し、利用者が誤検出を除外し見落としを追加できる画面を作る。候補数と人が確認した数を分ける。
5. 凡例の機器名・型番・用途と結び付け、確認した数量候補だけを既存の未確認積算候補へ渡す。元図面、検出/除外位置、確認者・日時を根拠に残す。採用済み明細を変更しない。
6. 同図面の凡例/図枠/詳細図は施工範囲から除く。重複ページ/別縮尺/系統図と平面図の同一設備を再加算しない。新設/撤去/存置の凡例が不明なら分類を確定しない。

## 実図面の受入条件

- 元PDF/TIFFの文字・記号が見える解像度で取得できる。
- 対象記号、対象範囲、手で数えた正解位置/個数が比較できる。
- 誤検出と見落とし、別方向/縮尺、未処理範囲を隠さない。
- 外部通信なしで動き、実工事33候補32採用等の既存データと正式Excelの採用条件を保持する。
