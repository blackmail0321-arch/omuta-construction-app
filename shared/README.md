# PC・iPad入力 → スマホで提出状況を確認

## 現在の範囲

- Supabase Authでログイン。工事の所有者が、登録済み利用者へ工事ごとに閲覧/編集権限を付与します。
- PC・iPadで共有済み工事を編集すると、約1秒後に工事JSONと提出状況を自動送信します。
- 別の編集端末では「端末間共有」から共有版を取り込みます。取り込み前に全工事のJSONバックアップをダウンロードし、採用件数・明細計を確認します。同じ工事の置き換え前には端末内にも復元用データを保存し、保存に失敗した場合は取り込みを中止します。端末内の既存データを無条件に消しません。
- スマホ画面は30秒ごと/画面へ戻った時に状況確認し、手動更新もできます。期限超過・差戻し・未確認・期限・提出日・確認日・備考を表示します。
- 閲覧専用アカウントは、DBのRLS/関数の権限検査で、工事金額JSONの取得・保存・権限変更を拒否されます。スマホ画面を隠すだけの制御ではありません。
- 同時編集は更新番号の一致を検査し、競合時に自動送信を停止します。端末内の変更を保持して、バックアップ後の共有版取り込みを案内します。自動的な上書き・マージはしません。
- 保存失敗は端末側で表示し、スマホは取得失敗時に「最新状態を取得できていない」と表示します。

**添付本体の同期は今回の範囲外です。** 元端末のIndexedDBに残ります。別端末で添付も扱う場合は「書類・分類ZIP」で保全・復元してください。JSONだけのバックアップに添付本体は含まれません。新しい共有DBの自動バックアップ方針は別途設定が必要です。

## 1. Supabaseプロジェクトを用意する（利用者の操作）

1. Supabaseの公式サイト https://supabase.com/ へログインし、組織内に新規プロジェクトを作ります。プラン・地域・利用条件を確認してください。こちらから有料契約や新規公開先は作成しません。
2. DBパスワードは安全な場所に保管します。チャット・ブラウザ用設定ファイルには入れません。
3. SQL Editorで [`db/001_shared_projects.sql`](db/001_shared_projects.sql) 全文を実行します。新規DBへ一度だけ適用します。テスト用bootstrap SQLは本番へ入れません。
4. Authenticationの設定で一般利用者の自由な新規登録を無効にします。管理者が必要な利用者だけをUsersから作成します（画面名はサービスの更新で変わる場合があります）。
5. PC/iPad用の編集アカウントと、スマホ用の閲覧専用アカウントを作成します。パスワードはチャットではなく安全な方法で本人へ渡してください。
6. 次のSQLを、作成したアカウントのメールアドレスへ書き換えて実行します。登録済みアドレスを使い、更新結果が想定人数か確認します。

```sql
-- PC・iPad編集用（実在する登録アドレスへ置換）
insert into public.shared_accounts(user_id, access)
select id, 'editor' from auth.users where email = 'editor@example.com'
on conflict(user_id) do update set access = excluded.access;

-- スマホ閲覧専用（別の登録アドレスへ置換）
insert into public.shared_accounts(user_id, access)
select id, 'viewer' from auth.users where email = 'viewer@example.com'
on conflict(user_id) do update set access = excluded.access;
```

同じ編集アカウントをスマホに入力しても、見た目が閲覧画面になるだけで、アカウント自体の編集権限は残ります。**サーバー側でも閲覧専用にするには `viewer` アカウントを使います。** どちらのアカウントも、共有されていない他人の工事は読めません。編集者の操作で閲覧専用アカウントを編集者へ昇格することはできません。

## 2. 接続設定

Supabaseのプロジェクト設定/APIから次の2項目を取得し、クラウド環境の環境変数設定へ登録してください。秘密値をチャットへ貼らないでください。

|環境変数|内容|
|---|---|
|`SUPABASE_URL`|`https://<project-ref>.supabase.co` 形式のProject URL|
|`SUPABASE_PUBLISHABLE_KEY`|ブラウザに公開可能なpublishableキー（`sb_publishable_…`）。従来のanonキーにも対応|

`service_role`、`sb_secret_…`、DBパスワード、利用者パスワードは使用禁止です。設定スクリプトとブラウザクライアントは管理用キーを拒否します。上の公開用キーは配信JSにも入るため、DBのRLSを必ず適用します。

クラウドから接続検証する際は、ネットワーク設定へそのプロジェクトの正確なホスト名を追加してください（例：`<project-ref>.supabase.co`）。接続先が決まる前に全Supabaseドメインを許可する必要はありません。

ビルド・設定：

```bash
cd apps/integrated-v0.13
python3 integrated/build.py
cp integrated/index.html index.html
cd ../..
python3 scripts/package_shared.py --output /tmp/omuta-shared-release
```

環境変数がある場合は公開用接続設定を組み込んだ配信物を作ります。未設定なら「共有先未設定」と表示し、共有を装いません。出力先は毎回新しいディレクトリを指定します。設定値はログに出しません。

既存の配信フォルダだけを設定する場合：

```bash
python3 scripts/configure_shared.py --app /path/to/editor-site
```

このスクリプトは環境変数を読み、配信物の `shared/shared-config.js` と `integrated/shared/shared-config.js` を更新します。秘密キーは決して配置しません。

## 3. HTTPSで配信する（新しい本番公開は別途確認）

SupabaseのDB作成だけではWeb画面の配信先はできません。組織で承認したHTTPS配信先を用意します。コードのGitHub保存・開発環境PublishもWebアプリの本番公開とは別です。

- `editor/`：PC/iPad用。既存の参考工事や原本テンプレートを含むため、社内または認証付きの配信先を使ってください。ログイン用CSSは静的ファイル自体を保護する認証の代わりにはなりません。
- `viewer/`：提出状況のみの独立したスマホ用サイト。`index.html` が入口です。原本Excel・積算コード・参考工事データ・テスト用認証サーバーを含みません。データAPIには常に認証と工事ごとの権限検査が掛かります。
- まず承認した同じ利用者で、PC/iPad編集用URLとスマホ確認用URLを開いて検証します。スマホへは確認用URLだけを案内します。
- 接続設定を含むHTTPS配信物を用意し、実際のSupabaseログイン・SQL適用・利用者権限を確認してから業務利用を開始します。実機Safari/Chrome、タッチ/キーボード・ファイル操作も検証します。

初回は各ブラウザから作業バックアップと書類・分類ZIPを保存し、実案件1件で採用件数・金額・提出状況・添付保全を照合してください。旧HTMLとバックアップは復元確認まで残します。

## 4. 日常操作

### PC・iPad

1. 編集用URLへアクセスし、編集用アカウントでログイン。
2. 初回の端末は、既存工事を復元/選択し「端末間共有」→「選択中の工事を共有・更新」。参考工事は共有できません。
3. 工事の所有者が同画面で相手の登録メールアドレスと「提出状況の閲覧のみ」を指定。
4. 別の編集端末は一覧の「共有版を取り込んで編集」を選択。件数・金額差分を確認し、先にJSONバックアップを保存します。
5. 編集後は上部の「端末内・共有先とも保存済み」を確認。「共有待ち」「通信失敗」のままではスマホへ反映されません。
6. 競合が表示された場合は入力を続ける前に端末内のバックアップを保存し、一覧更新→共有版の取り込みで内容を比較します。後勝ちの自動上書きは行いません。「選択中工事を取り込み前に戻す」でも端末内の復元用データへ戻せます（共有先へは自動送信せず、内容比較を求めます）。

### スマホ

1. スマホ用URLを開き、閲覧専用アカウントでログイン。
2. 工事と月次対象月を選択。期限超過・差戻しなどで絞り込みます。
3. 「最新の状態に更新」と、共有データの更新日時を確認。PCが未送信/オフラインの変更はまだ表示されません。
4. 使い終わったらログアウト。ログイン状態はタブのセッション内に保持します。共用端末では利用後に閉じ、端末の画面ロックも使用します。

## 検証済みと残り

- 実PostgreSQLでRLS、閲覧者/未共有者/匿名拒否、機密データの除外、権限変更、更新番号競合、共有解除、期限・材料変更状態を検証。
- 実PostgREST＋PostgreSQLのブラウザテストで、PC共有→スマホ確認、iPad取り込み/バックアップ、変更の自動送信、通信失敗時の保持・再送、競合、期限切れセッション更新、共有解除、ログアウト、スマホ画面への誘導を検証。Auth部分のみローカルテスト代替で、本物のSupabase Authの接続検証はまだです。
- **未実施**：利用者の本物のSupabase接続、本番HTTPS配信、実案件移行、Windows/Mac/iOS/Android実機、添付本体の共有、自動DBバックアップの運用検証。

既存の積算・Excel・単価計算はこの共有機能の導入で置換しません。AIによる工事知識蓄積は次の別段階です。

利用者のiPad mini/Safariで、Cloudflare Access認証、Supabase編集・閲覧ログイン、動作確認用工事の共有、提出状態の変更が閲覧サイトへ反映されることを確認しました。職場PCはi-FILTERにより接続できず、利用許可が必要です。iPhone/Android実機とPCからの入力共有は未確認です。
